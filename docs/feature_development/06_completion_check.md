## ローカルで Notion と繋ぐ

### 必要なもの

内部インテグレーションは、公開サーバーもリダイレクトURIも要りません。
**localhost からそのまま API を呼べます。**

```
□ Notion のインテグレーショントークン
□ 書き込み先のページ（インテグレーションに許可済み）
□ そのページのID（URLの32文字）
```

### 手順

```bash
# 1. トークンを環境変数に設定
echo 'NOTION_API_KEY=ntn_xxxxx' >> backend-clean/.env

# 2. 起動
docker compose up -d

# 3. マイグレーション
cd backend-clean && make migrate-up

# 4. テンプレート編集画面で、許可済みページのURLを設定
```

> **Notion 側の準備を忘れずに**
> ページをインテグレーションに許可していないと、
> `object_not_found` (404) が返ります。
> 「トークンは正しいのに404」の原因はほぼこれです。

## 実機で確認する

モックでは見つからない問題が出る場所です。

```
□ 実際に Notion にページができる
□ タイトルが文字化けしない（日本語）
□ 絵文字が壊れない
□ セクションの見出しが意図どおりに出る
□ 改行が保たれている
□ 長い本文が途中で切れない
□ 非公開に戻すとNotionから見えなくなる
□ 再公開で同じページが戻る（URLが変わらない）
```

> **文字化けとブロック分割はモックで見つからない**
> httptest は「こちらが送った内容」しか検証しません。
> Notion 側でどう見えるかは、本物でしか確認できません。

## つまずきやすい箇所

実際に動かすと、ここで止まります。

| 症状 | 原因 | 対処 |
|---|---|---|
| `object_not_found` (404) | ページをインテグレーションに許可していない | Notion でページに接続を追加する |
| `unauthorized` (401) | トークンが違う / 期限切れ | トークンを再確認 |
| `validation_error` (400) | 親の種類とプロパティが不一致 | ページ配下なら `title` のみ |
| 本文が途中で切れる | 1リクエストのブロック上限（100） | 分割して送る |
| 文字化け | Content-Type の指定漏れ | `application/json` を明示 |

> **404 が一番多い**
> 「トークンは合っているのに見つからない」と言われたら、
> まず許可設定を疑います。

## 実務ではこの先がある

この教材はローカルでの動作確認までですが、
実際に本番へ出すなら、この章の後にもう一段あります。

```
□ 本番のNotionワークスペースを決める
□ 本番用トークンをシークレット管理に登録する
□ 既存の公開済みノートをどうするか決める
   → 全テンプレートに親ページを設定してからリリース
□ 連携失敗の件数を監視する
   → status='failed' が急増したらNotion障害かトークン失効
□ 障害時にどう止めるか決めておく
   → NOTION_API_KEY を空にすれば連携だけ止まる
```

> **「設定で止められる」ようにしておく意味**
> 第2章で「設定未投入でも起動する」設計にしました。
> これは開発の都合だけでなく、
> **障害時の止血弁**としても効きます。
